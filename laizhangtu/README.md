# laizhangtu · 来张图

RainCough 面板（v4 接口库）插件：按标签从 Lolicon 公开 API **搜索一组作品并浏览选择**，
也可以直接随机抽一张；选中的图在服务端做翻转 / 随机模糊处理后落到本地缓存，
通过面板页面浏览并保留历史记录。

由 `E:/jiaob/来张图` 的 QQ 脚本插件（`main.java` + WebView 设置页）迁移而来，
原始源码归档在 `legacy/`。与面板内置的 `laizhangsetu` 是**两个不同插件**（名称与接口前缀不同），
可以同时安装；本插件的定位是可分发的市场版。

## 安装

- **插件市场**：面板 →「插件」→「插件市场」→ 找到「来张图」→ 安装（需先 `python gen_registry.py` 更新索引并提交仓库）。
- **离线包**：把本目录打成 `.zip`（根目录含 `plugin.json`），面板 →「插件」→「安装插件」上传。
- **手动**：`cp -a laizhangtu /path/to/raincough/plugins/` 后重启面板，并在「服务」里设为开机自启。

### 依赖

`plugin.json` 的 `requirements` 已声明，面板启动前会预检：

```bash
python3 -m pip install "requests>=2.31" "pillow>=9"
```

后端用 `python3 server_v4.py` 启动，SDK `rcplugin.py` 无第三方依赖。
需要外网访问 `api.lolicon.app` 与图片代理域名（默认 `i.pixiv.re`）。

## 接口

| 接口 | 说明 |
|---|---|
| `laizhangtu.info` | 插件信息与能力说明 |
| `laizhangtu.config.get` / `.save` | 读取 / 保存配置（含取值范围校验） |
| `laizhangtu.fetch` | 随机取一张图；参数 `tag`（表达式）、`r18`（可选覆盖）、`tags`（数组，可选） |
| `laizhangtu.search` | 按标签搜索，一次返回最多 20 条**元数据**（不下载图片、不写历史）；参数 `tag`/`tags`、`num`（1-20，默认 8）、`r18` |
| `laizhangtu.pick` | 从最近一次搜索结果里按 `id` 选中指定作品，下载处理后落盘；参数 `id` |
| `laizhangtu.history.list` / `.clear` | 历史记录 |
| `laizhangtu.cache.stats` / `.clear` | 缓存占用 / 清空缓存与历史 |

标签表达式沿用原脚本语法：`A|B` 表示「或」，`A&B` 表示「与」；逗号、空格也按「与」拆分，
最多 5 组。例如 `猫耳|制服&白丝` 表示「（猫耳或制服）且白丝」。留空则随机。

## API 搜索能力（实测，2026-11-07 本机）

`setu/v2` 是**唯一端点**，没有独立的搜索接口；搜索靠 `tag` / `keyword` 参数完成。
下表为对照实验结果（均为 `r18=0`、`excludeAI=true`、`proxy=i.pixiv.re`）：

| 探测 | 结果 | 结论 |
|---|---|---|
| `tag=猫耳` / `白丝` / `制服` / `星空` / `风景`，`num=3` | 各返回 3 条，**3/3 命中** | `tag` 是真过滤，不是忽略参数后随机返回 |
| `tag=不存在的词` | 返回 **0 条**，`error=''` | 无命中就是空数组，插件据此提示「没有找到…」 |
| 两个 `tag` 参数（猫耳 + 白丝） | 3/3 同时含两标签 | 多 `tag` = **AND** |
| 单个 `tag=猫耳|白丝` | 3/3 含其一 | 组内 `|` = **OR** |
| `tag=猫耳|白丝&tag=制服` | 3/3 满足「(猫耳或白丝) 且 制服」 | 与/或混合可用，与 `parse_tag_expr` 展开一致 |
| 同一标签连查两次 | PID 完全不同 | 语义是**「在命中集合里随机抽样」**，不是固定排序的搜索列表 |
| `tag=猫` | 3/3 标签里都含「猫」 | 标签是**模糊/部分匹配**，不是精确等值 |
| `keyword=猫耳` / `keyword=不存在的词` | 3 条全命中 / 0 条 | `keyword` 也是过滤参数 |
| `tag=猫耳 + keyword=白丝` | 3/3 含白丝 | 两个条件同时生效 |
| `pid=123456` / `pid=999999999999` | 都返回 1 条随机作品 | **`pid` 被忽略**，不能按作品 ID 精确取图 |
| `num=1/5/10/20/21/25/30` | 1/5/10/20/**0/0/0** 条 | **上限 20**；超出静默返回空（HTTP 200、`error=''`），不报错 |

其他两点：

- **限流**：短时间连续高频探测时遇到过 HTTP 429（JSON `error` 形如「请求的太…」），
  等待约 20 秒后恢复；正常使用（一次取一张）不会触发。插件连续重试最多 8 次，
  若标签很冷门又叠加限流，可能看到 429 提示，稍等再试即可。
- **官方文档站当前不可用**：`api.lolicon.app` 跳转到 `docs.api.lolicon.app`，两者都返回
  GitHub Pages 404，所以上述语义全部以实测为准。

对本插件的影响（v1.1.0 起已实现）：`fetch` 仍固定 `num=1` 取 `data[0]`（随机抽一张），
另设 `search` 一次取最多 20 条构成结果列表。因为 `num>20` 会静默返回空，后端把 `num`
强制夹在 1–20；又因为 `pid` 被忽略，选中结果必须靠服务端会话复现（见下节）。

> 以上为单次本机实测值，API 行为与网络状况可能随时间变化，仅作开发/排障参考。

## 搜索结果列表

「搜索」页输入标签 → 点「开始搜索」→ 列出最多 20 条元数据卡片（标题、作者、PID、尺寸、
标签、规格）→ 点「取这张」才会下载并保存到本地缓存，随后自动切回取图页展示。

设计要点：

- **为什么需要 `pick` 接口**：实测 `pid` 参数被 API 忽略，按 PID 再请求会拿到另一张随机作品，
  所以无法「记住 pid 再取图」。`search` 把每条结果的图片地址暂存在**服务端内存会话**里，
  只给前端一个随机 `id`；`pick` 用这个 `id` 取回同一张图，全程不重新搜索（测试中已验证
  `pick` 阶段只有一次图片下载、没有任何 API 搜索请求）。这也避免前端回传任意 URL 造成 SSRF。
- **会话有效期**：30 分钟，仅存内存；插件重启后需重新搜索。超过 200 条会淘汰最旧记录。
- **不预下载**：`search` 只发一次 API 请求（实测约 1.4 s），不下载图片、不写历史、不落盘，
  因此不会触发图片代理的慢速问题。搜索总预算封顶 20 秒。
- **缩略图默认关闭**：卡片里的 `thumb` 是第三方代理 URL。勾选「显示缩略图」后由浏览器直接
  加载（不经过插件后端），加载失败会自动隐藏；默认关闭以避免主动请求第三方内容。
- **内容过滤逐条生效**：每条结果的标题/标签都过 `_BLOCKED`，命中即丢弃并在结果栏显示
  「过滤 N 条」。真实 API 实测 `num=5` 返回 5 条、可用 3 条、过滤 2 条。
- **限流**：连续高频搜索会触发 HTTP 429 或 JSON `error` 里的限流文案，插件已统一转成
  「请稍等 20~30 秒再试」的中文提示，不再误报为「更换代理域名」。
- **规格**：搜索按当前「图片规格」设置请求，`pick` 用的就是那次返回的 URL。选了原图又下载
  失败时不会换成别的作品，会提示把规格改成小图后重新搜索。

## 配置项

| 字段 | 默认 | 对应原脚本 |
|---|---|---|
| `show_info` | `true` | 「信息」开关 |
| `exclude_ai` | `true` | 「排除AI」 |
| `flip_h` / `flip_v` | `true` / `false` | 「翻转」/「垂直翻转」 |
| `blur_chance` | `5`（0-100） | 「冲多了」概率 |
| `img_size` | `2` 小图 | 「图片质量」0 原图 / 1 regular / 2 small |
| `proxy` | `i.pixiv.re` | 图片代理；实测只有这个域名稳定可用，`pixiv.re` 会返回 404 |
| `r18` | `false` | R18 开关（开启后 API 参数 `r18=2`） |
| `exclude_seen` | `false` | 新增：跳过已取过的 pid |
| `cool_down` | `0`（秒） | 「冷却时间」，前端倒计时 + 后端限流 |
| `max_cache_mb` | `256` | 新增：缓存上限，超限删最旧 |
| `fetch_timeout` | `20`（5-180 秒） | 新增：整次取图的总预算；前端按同值 +5s 放宽面板 invoke 超时 |

搜索结果条数 `num` 是「搜索」页的临时选项（5 / 8 / 10 / 20，默认 8），不写入配置文件；
后端始终把它夹在 1–20。

QQ 消息相关的自动撤回、@ 提醒、卡片消息、按群开关、悬浮窗设置无法迁移，已在 `legacy/README.md` 说明。

## 超时与故障排查

面板 `invoke` 默认只等 **15 秒**（`RainCough-Core/internal/pluginx/http.go`）。实测网络数据
（2026-11-07，本机）：

| 环节 | 实测 |
|---|---|
| DNS `api.lolicon.app` / `i.pixiv.re` | 24–50 ms，正常 |
| 搜索接口 `setu/v2` | HTTP 200，**1.3–1.9 s**，字段齐全 |
| 图片代理首字节（TTFB） | **2.3–7.0 s** |
| `size=original` 图片 | 约 1.5–2.0 MB，全量下载 **71 s** |
| `size=small` 图片 | 约 **29 KB**，通常数秒内完成 |

所以「搜索超时」不是 API 不通，而是**原图下载太慢 + 面板 15 秒超时**。本插件的处理：

- 默认 `img_size=2`（小图），让一次取图通常落在 15 秒内。
- `fetch` 全程由单调时钟预算 `fetch_timeout` 约束；`requests` 的 read timeout 管不到
  「每秒来几个字节」的慢速滴流，因此下载时逐块检查预算并主动掐断。
- 选了原图 / 中等却超时或失败时，若预算还够，自动重新请求 `size=small` 并把代理换回
  `i.pixiv.re`；返回记录带 `degraded: true`，页面会提示「已自动降级为小图」。
- 搜索接口超时、连接失败、HTTP 404/5xx、图片超时都会转成中文提示，并给出下一步建议；
  失败不消耗冷却时间。
- 前端调用 `laizhangtu.fetch` / `laizhangtu.pick` 时显式传 `timeoutMs = (fetch_timeout + 5) * 1000`，
  因此把预算调到 60 秒以上时面板不会先掐断；`laizhangtu.search` 只发一次 API，
  传 `(min(fetch_timeout, 20) + 5) * 1000`，不会因搜索本身超时。

如果仍然失败，依次检查：① 图片规格改成「小图 small」；② 代理域名保持 `i.pixiv.re`；
③ 把「取图超时」调到 60 秒以上；④ 确认面板机能访问 `api.lolicon.app` 与 `i.pixiv.re`。
若是从其他插件/脚本直接调 `laizhangtu.fetch`（没有前端的 `timeoutMs`），请自行传
`timeout_ms`，或把 `fetch_timeout` 保持在 15 秒以内。

> 上述为单次本机实测值，网络状况随时变化，仅作排障参考，不保证其他环境一致。

## 内容安全与合规

- **不分发任何图片素材**：原目录的 `缓存/` 图片没有打包进插件；缓存只在运行时按需生成。
- **硬性内容过滤**：`server_v4.py` 的 `_BLOCKED` 规则同时校验「输入标签」与「API 返回作品的标题/标签」，
  命中涉及未成年人性化的表述即拒绝请求或丢弃该作品并重试。搜索结果列表**逐条**应用同一规则
  （丢弃数会显示在结果栏），`pick` 取出会话里的作品时再校验一次。前端也做同一规则的即时提示，
  但后端是唯一权威校验点（直接调接口也拦得住）。
- `r18` 默认关闭；标签示例与使用说明均已用中性表述重写。
- 插件仅限**成年人在本地个人环境**使用，图片来自第三方公开 API，内容由使用者自行判断；
  请遵守所在地法律法规，不得用于传播违法内容，也不要将面板暴露到公网。

## 构建前端

改动 `frontend/plugin.js` 后需重新生成 `assets/plugin.js`：

```bash
# 在 RainCough-Plugin 仓库根目录；Vue/esbuild 复用同级 RainCough-Core/web/node_modules
node tools/build-plugin-frontend.cjs laizhangtu
# 面板仓库在别处时：RC_CORE_DIR=/path/to/RainCough-Core node tools/build-plugin-frontend.cjs laizhangtu
```

新增或修改插件后，在仓库根目录运行 `python gen_registry.py` 重新生成 `registry.json`。
